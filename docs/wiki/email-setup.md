# Email (Docker-Mailserver + Roundcube)

**Category:** `email` · **Placement:** `control` · **Route:** `mail.<domain>` (private, Roundcube webmail)

## Architecture

| Component | Service | Port | Purpose |
|-----------|---------|------|---------|
| Postfix | mailserver | 25, 465, 587 | SMTP send/receive |
| Dovecot | mailserver | 143, 993 | IMAP mailboxes |
| Rspamd | mailserver | internal | Spam filter + DKIM signing |
| Roundcube | roundcube | 80 (via Caddy) | Webmail frontend |

Authentication is via **LLDAP bind auth** — Dovecot opens a fresh LDAP
connection as the logging-in user to verify their password. This is the
only auth mode that works with LLDAP (which intentionally hides
`userPassword` hashes from bind users).

## DNS records

Published by `homelab-toolkit dns sync` (Cloudflare):

| Record | Value |
|--------|-------|
| MX | `10 mail.<domain>` |
| A | `mail.<domain>` → public IP (unproxied) |
| TXT (SPF) | `v=spf1 ip4:<ip> mx -all` |
| TXT (DMARC) | `v=DMARC1; p=quarantine; rua=mailto:dmarc@<domain>` |
| TXT (DKIM) | `v=DKIM1; k=rsa; p=<key>` at `mail._domainkey.<domain>` |
| CNAME | `autoconfig.<domain>`, `autodiscover.<domain>` → `mail.<domain>` |

DKIM keys are generated by Rspamd on first boot (`setup config dkim`)
and published to Cloudflare by the `dns sync` step after deploy hooks run.

## Ports

The mail plugin declares its protocol listeners. Generation opens LAN/mesh access and
DNATs WAN 25/465/587/993 to the manifest-selected mail machine only when both
`network.expose_via_internet` and `network.mail_public_access` are true.

| Port | Protocol | Purpose |
|------|----------|---------|
| 25 | SMTP | Inbound mail (no auth) |
| 465 | SMTPS | Implicit TLS submission (if SSL configured) |
| 587 | Submission | Authenticated outbound (STARTTLS) |
| 993 | IMAPS | Implicit TLS IMAP (if SSL configured) |

ManageSieve `4190` is available only from the private LAN and mesh. It is not exposed
to the public internet by default.

## Accessing mail

- **Webmail:** `https://mail.<domain>` (Roundcube — forward-auth protected)
- **IMAP:** `mail.<domain>:993` (implicit TLS)
- **SMTP:** `mail.<domain>:587` (STARTTLS)
- **Login:** your LLDAP username (e.g. `owner`) or email (`owner@<domain>`)

## Internal relay

Other Docker containers send email via `mailserver:25` (no auth needed
on the internal Docker network). The generated `.env` sets:
```
SMTP_HOST=mailserver
SMTP_PORT=25
```
